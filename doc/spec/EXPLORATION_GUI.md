# 探索画面 — 要件定義

## Context

Cognac の既存タスクは「実装すること」が前提になっている。
一方で、実装前に以下を行いたいケースが多い。

- 仕様相談
- 画面/UI の確認
- バグ再現
- Playwright を使った探索
- モンキーテスト
- 課題整理と次アクションの洗い出し

これらはコード変更を伴わないが、AI に考えさせてレポートまで返したい。
また、結果からそのまま AI にタスク生成させたい。

そのため、実装タスクとは別に `探索` 画面を新設する。

---

## 目的

- 実装を行わず、依頼内容に対する調査・検証・整理を AI に実行させる
- ペルソナ選定とディスカッションを通して、AI が自律的に進め方を判断する
- 必ず最終レポートを生成する
- 必要であればレポートからそのまま AI に複数タスクを生成させる

---

## この画面でやること

- タイトル・本文・画像をもとに探索依頼を作成する
- AI がペルソナを選定する
- AI が内部ディスカッションを行い、何をすべきか判断する
- 必要に応じて以下を実行する
  - 調査
  - 方針整理
  - Playwright による画面確認
  - モンキーテスト
  - 証跡画像の取得
- 最終レポートを作成する
- レポートから AI にタスクを自動生成させる

## この画面でやらないこと

- コード修正
- Git ブランチ作成
- CI 実行
- main へのマージ

---

## 体験の基本方針

- ユーザーに実行タイプは選ばせない
- ユーザー入力は `タイトル + 本文` を必須とし、画像添付は任意とする
- URL / タスク / ブランチの入力欄は設けない
- AI は依頼内容と添付画像を見て、自分で進め方を判断する
- ペルソナ選定とディスカッションは省略しない
- ディスカッションは結果画面でしっかり見せる
- すべての探索はレポート完成までを成功条件とする

---

## 画面構成

### 一覧画面

既存のタスク一覧に近い体験で、過去の探索セッションを再確認できるようにする。

表示項目:

- タイトル
- 状態
- 作成日時
- 更新日時
- 最終レポート有無
- 課題件数

状態候補:

- `draft`
- `analyzing`
- `reporting`
- `completed`
- `paused`
- `failed`

### 新規作成

入力項目:

- タイトル 必須
- 本文 必須
- 画像添付 任意、複数枚可

画像用途:

- 相談の前提資料
- 現状画面のキャプチャ
- バグ報告の補足

### 詳細画面

既存のタスク詳細に近い構成を採用する。

推奨タブ:

- `概要`
- `ディスカッション`
- `ログ`
- `レポート`

#### 概要

- 元の依頼タイトル
- 元の依頼本文
- ユーザー添付画像のサムネ一覧
- 状態
- 実行開始 / 完了時刻

#### ディスカッション

- 選定されたペルソナ一覧
- ラウンドごとのディスカッションログ
- AI が探索方針をどう判断したか追えること

#### ログ

- 探索中のイベントログ
- Playwright 実行ログ
- エラーやリトライ情報

#### レポート

レポートは毎回以下 5 ブロック固定とする。

- `結論`
- `調査内容`
- `ディスカッション要約`
- `課題`
- `次アクション`

レポート下部に `証跡画像` セクションを追加し、Playwright が取得した画像を小さなサムネイルで表示する。
表示イメージはタスク作成画面の画像プレビューに近いものとする。

---

## 実行フロー

1. ユーザーが探索依頼を作成する
2. AI がペルソナを選定する
3. AI がディスカッションを実行し、探索方針を決める
4. 必要に応じて調査・Playwright・モンキーテストを実行する
5. 証跡や観測結果を収集する
6. 固定フォーマットのレポートを生成する
7. 必要に応じて `AIでタスク化` を実行する

---

## AIでタスク化

### 基本方針

レポート閲覧後、ユーザーは `AIでタスク化` ボタンを押せる。
押下後は確認ステップを挟まず、AI がそのままタスクを自動生成する。

### AI に任せること

- 課題の粒度分解
- 複数タスクへの分割
- 各タスクのタイトル生成
- 各タスクの説明文生成
- 各タスクの priority 自動判定
- 画像の自動選別

### 画像引き継ぎ

タスク生成時、AI は以下の画像を入力素材として扱う。

- ユーザーが探索依頼時に添付した画像
- Playwright が探索中に取得した証跡画像

AI は各生成タスクに対して、必要な画像だけを選んで引き継ぐ。
全画像を機械的に全タスクへ付与しない。

---

## Playwright / 画像まわり

- Playwright 実行は AI 判断でのみ行う
- ユーザーに `Playwright 実行あり/なし` を選ばせない
- Playwright 実行時は、ログに訪問・操作・結果を残す
- 必要に応じてスクリーンショットを保存する
- 保存した画像は探索詳細のレポート下部に表示する
- 保存した画像は後続のタスク生成でも再利用可能にする

## データ設計の方向性

既存 `tasks` とは別系統のデータとして持つ。

### `exploration_sessions`

- id
- title
- request
- status
- final_report_markdown
- created_at
- started_at
- completed_at

### `exploration_images`

- id
- exploration_session_id
- source_type (`user` | `playwright`)
- file_path
- original_name nullable
- mime_type
- created_at

### `exploration_personas`

- id
- exploration_session_id
- persona_id
- name
- focus
- tone
- created_at

### `exploration_discussions`

- id
- exploration_session_id
- round
- persona_id
- persona_name
- content
- should_continue
- continue_reason
- created_at

### `exploration_artifacts`

- id
- exploration_session_id
- kind (`plan` | `playwright-log` | `report` | `finding`)
- content_text nullable
- file_path nullable
- created_at

## API の方向性

```
GET    /api/explorations
POST   /api/explorations
GET    /api/explorations/:id
GET    /api/explorations/:id/stream
GET    /api/explorations/:id/images
POST   /api/explorations/:id/retry
POST   /api/explorations/:id/taskify
```

### `POST /api/explorations`

- タイトル
- 本文
- 画像ファイル複数

### `POST /api/explorations/:id/taskify`

入力:

- 対象 exploration id

サーバー側の処理:

- レポートと課題を読む
- 画像を読む
- 複数タスクを生成する
- 必要画像を各タスクへ紐付ける

---

## UI 要件

- PC サイドバーに `探索` を追加する
- SP ボトムナビに `探索` を追加する
- タスク詳細に近い構造で、探索詳細を閲覧できる
- レポート下部の証跡画像はサムネイル一覧にする
- `AIでタスク化` はレポート画面の主要アクションとして配置する
- ペルソナとディスカッションは隠さず、明確に見えるようにする

---

## 受け入れ条件

- タイトル・本文だけで探索を開始できる
- 画像を複数添付して保存できる
- 探索時にペルソナ選定とディスカッションが実行される
- AI が依頼内容から進め方を判断する
- 毎回 5 ブロック固定レポートが生成される
- Playwright 実行時は証跡画像が保存され、レポート下部にサムネ表示される
- `AIでタスク化` で複数タスクが自動生成される
- 生成タスクの priority は AI が自動設定する
- 生成タスクには AI が必要と判断した画像だけが引き継がれる
- 探索履歴を一覧から再確認できる
