# 共通ステータスモデル移行計画

仕様: `doc/spec/STATUS.md`

## 概要

タスクと探索のステータスを7つの共通ステータスに統一する。

- タスク: `planned` を `discussing` に統合、`testing` → `reviewing` にリネーム
- 探索: `analyzing` + `current_phase` の二層構造を廃止、`failed` → `stopped` にリネーム
- フィルターカテゴリとアクション制御をタスク・探索で完全共通化

## ステップ

### Step 1: shared 型定義の変更

**対象ファイル:**
- `shared/types/task.ts` — `TaskStatus` から `planned` を削除、`testing` → `reviewing`
- `shared/types/exploration.ts` — `ExplorationStatus` を TaskStatus と同じ7値に変更、`ExplorationPhase` 型を削除、`ExplorationSession.current_phase` を削除
- `shared/index.ts` — `ExplorationPhase` のエクスポートを削除

### Step 2: DBスキーマ変更

**対象ファイル:**
- `server/db/schema.ts`
  - tasks テーブル: CHECK制約から `planned` 削除、`testing` → `reviewing`
  - exploration_sessions テーブル: `current_phase` カラム削除、status CHECK制約を新ステータスに変更

**注意:** 未リリースのためマイグレーション不要。DB削除→再作成でOK。

### Step 3: DBクエリ更新

**対象ファイル:**
- `server/db/queries/tasks.ts` — `stopAllActiveTasks()` の WHERE句を更新（`planned` 削除、`testing` → `reviewing`）
- `server/db/queries/explorations.ts` — `UpdateExplorationData` から `current_phase` 削除、`markExplorationFailed()` → `markExplorationStopped()` にリネーム、`getNextDraftExploration()` の status 条件確認

### Step 4: タスクランナー更新

**対象ファイル:**
- `server/runner/task-runner.ts`
  - `planned` ステータスへの遷移を `discussing` に変更（計画フェーズは discussing の一部）
  - `testing` → `reviewing` に全箇所リネーム
  - パイプラインコメントの更新

### Step 5: 探索ランナー更新

**対象ファイル:**
- `server/runner/exploration-runner.ts`
  - `status: 'analyzing'` → フェーズに応じた具体ステータスに変更:
    - persona 開始時: `status: 'discussing'`
    - discussion 開始時: `status: 'discussing'`（変更なし）
    - explore 開始時: `status: 'executing'`
    - report 開始時: `status: 'reviewing'`
  - `current_phase` の更新処理をすべて削除
  - `markExplorationFailed()` → `markExplorationStopped()` に変更

**注意:** `ExplorationPhase` 型はランナー内部のフェーズ管理（SSEイベント等）では引き続き使う可能性がある。ステータスとは別にランナー内部の処理フローとして `phase` 変数を残すかどうか要確認。
→ SSEイベントの `phase_start` / `phase_end` は内部イベントとして残す。型を `ExplorationPhase` ではなく文字列リテラルユニオンとして runner 内に閉じ込める。

### Step 6: API更新

**対象ファイル:**
- `server/api/tasks.ts` — cancel エンドポイントの status チェックから `planned` 削除、`testing` → `reviewing`
- `server/api/explorations.ts`
  - retry: `['paused', 'failed']` → `['paused', 'stopped']`
  - delete: `analyzing` チェック → `discussing`, `executing`, `reviewing` のいずれかなら拒否
  - 停止（キャンセル）エンドポイントを新規追加: `POST /:id/cancel`

### Step 7: CSSデザイントークン更新

**対象ファイル:**
- `client/index.css`
  - `--status-planned` / `--status-planned-bg` を削除
  - `--status-testing` / `--status-testing-bg` → `--status-reviewing` / `--status-reviewing-bg` にリネーム
  - light/dark 両モード + `@theme inline` の3箇所

### Step 8: クライアント ステータス設定更新

**対象ファイル:**
- `client/lib/status-config.ts`
  - `ACTIVE_STATUSES`: `planned` 削除、`testing` → `reviewing`
  - `STATUS_PHASE_MAP`: `planned` エントリ削除、`testing` → `reviewing`
  - `STATUS_CONFIG`: `planned` 削除、`testing` → `reviewing`
- `client/lib/exploration-status-config.ts`
  - `ExplorationCardStatus`: `analyzing` → `discussing` / `executing` / `reviewing` に分割
  - `EXPLORATION_DELETABLE_STATUSES`: `failed` → `stopped`、`paused` 追加
  - `EXPLORATION_RETRYABLE_STATUSES`: `failed` → `stopped`
  - `EXPLORATION_ACTIVE_STATUSES`: `analyzing` → `discussing`, `executing`, `reviewing`
  - `EXPLORATION_STATUS_CONFIG` / `EXPLORATION_CARD_STATUS_CONFIG`: analyzing エントリ削除、新ステータス追加
  - `getExplorationCardStatus()` 関数を削除（フラットステータスで不要に）

### Step 9: クライアント ページ・コンポーネント更新

**対象ファイル:**
- `client/pages/dashboard.tsx` — フィルター定義: `executing` カテゴリから `planned` 削除、`testing` → `reviewing`
- `client/pages/exploration-list.tsx` — フィルター定義: `analyzing` → `executing` カテゴリに変更、ステータスマッピング更新
- `client/pages/exploration-detail.tsx` — SSE接続条件: `analyzing` → `discussing || executing || reviewing`
- `client/components/task-card/` — `testing` → `reviewing` テキスト更新
- `client/components/status-badge/` — 新ステータスに対応
- `client/components/ui/badge.tsx` — `planned`, `testing` のスタイル → `reviewing`
- `client/components/__mocks__/task-data.ts` — テストデータ更新

### Step 10: 探索のキャンセル機能実装

現状、探索には停止機能がない。新ステータスモデルでは Executing フィルター内のステータスで停止可能。

**対象ファイル:**
- `server/api/explorations.ts` — `POST /:id/cancel` エンドポイント追加
- `server/runner/exploration-runner.ts` — AbortController の外部公開、キャンセル処理追加
- `client/hooks/use-explorations.ts` — `useCancelExploration()` hook 追加
- `client/pages/exploration-detail.tsx` — 停止ボタン追加

### Step 11: 探索の編集機能実装

現状、探索にはタイトル・本文の編集機能がない。

**対象ファイル:**
- `server/api/explorations.ts` — `PUT /:id` エンドポイント追加（pending/completed/paused/stopped のみ）
- `server/db/queries/explorations.ts` — 更新クエリ追加
- `client/hooks/use-explorations.ts` — `useUpdateExploration()` hook 追加
- `client/pages/exploration-detail.tsx` — 編集UI追加

### Step 12: typecheck & ビルド確認

```bash
pnpm typecheck
pnpm build
```

## 実装順序の理由

1. **Step 1-3 (型・DB)** を最初に行うことで、TypeScript が全箇所のエラーを教えてくれる
2. **Step 4-6 (サーバー)** でバックエンドを先に完成させる
3. **Step 7-9 (クライアント)** でフロントを合わせる
4. **Step 10-11 (新機能)** は既存の修正後に追加
5. **Step 12** で最終確認
