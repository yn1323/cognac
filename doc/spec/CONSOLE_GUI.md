# コンソール画面 — 要件定義

## Context

Cognac を使うとき、日常的に以下のようなローカルコマンドを起動したい。

- `pnpm dev`
- `pnpm storybook`
- `pnpm test --watch`
- 各種開発サーバー
- 単発の補助コマンド

これらを VSCode やターミナルで毎回手入力するのは面倒であり、起動状態やログも GUI 上で確認したい。

そのため、登録済みコマンドを標準運用として扱う `コンソール` 画面を新設する。

---

## 目的

- ローカルコマンドを登録して永続化する
- ワンクリックで起動できる
- GUI でログをリアルタイム表示する
- `Ctrl+C` 的な停止を行える
- 実行履歴を短期保存し、あとから見返せる

---

## 体験の基本方針

- `コンソール` は個人向け便利機能ではなく標準運用画面として扱う
- 長時間常駐コマンドと単発コマンドの両方を主対象にする
- 実行ディレクトリは常にリポジトリルート固定とする
- 子階層での実行が必要な場合は、コマンド定義側で吸収する
- 同じコマンドを再実行した場合は上書き再起動する
- 別コマンド同士は同時実行を許可する

---

## 画面構成

### 一覧 + ログの 2 ペイン

主画面は以下の構成とする。

- 左または上段: コマンド定義一覧
- 右または下段: 選択中コマンドの最新ログ

### コマンド定義一覧

各カードまたは行に表示するもの:

- 表示名
- 実コマンド
- 状態
- 最終実行時刻
- アクション
  - 実行
  - 停止
  - 編集
  - 削除
  - 履歴表示

状態候補:

- `idle`
- `starting`
- `running`
- `stopping`
- `completed`
- `failed`
- `killed`

### ログペイン

- 選択中コマンドの最新 run のログを表示する
- 実行中は自動追従する
- 過去 run を切り替えて見られる
- exit code と開始/終了時刻を表示する

---

## コマンド登録

登録項目:

- 表示名
- コマンド
- 任意メモ

保持方針:

- コマンド定義は永続化する
- 実行ディレクトリ指定欄は設けない
- 環境変数編集 UI は MVP では持たない

---

## 実行ルール

### 同じコマンドの再実行

- 実行中の run を停止する
- 停止完了後に新しい run を開始する
- 二重起動はしない

### 別コマンドの同時実行

- 許可する
- 例: `pnpm dev` と `pnpm storybook` を同時に起動できる

### 単発コマンド

- 実行完了後に `completed` または `failed` になる
- ログは履歴として残る

### 常駐コマンド

- 実行中は `running`
- 停止要求時は `stopping`
- 停止完了後に `killed` または適切な終了状態へ遷移

---

## 停止仕様

停止は `Ctrl+C 的な停止` を第一選択とする。

1. まず穏当に停止要求を送る
2. 一定時間で止まらない場合は強制終了する
3. 必要ならプロセスツリーごと止める

Windows / Mac 両方で同等の体験になるように、実装側で OS 差分を吸収する。

---

## ログ保存

### 保存方針

- コマンド定義と run メタデータは SQLite に保存する
- ログ本文はファイル保存する

理由:

- `pnpm dev` などはログ量が多い
- DB に全文保存すると肥大化しやすい
- 短期保存ログはファイルの方が扱いやすい

### 保存期間

- ログ本文: 24 時間保持
- run メタデータ: 24 時間保持、または対応ログ削除時にあわせて削除

クリーンアップ:

- サーバー起動時に実施
- 一定間隔でも実施

---

## データ設計の方向性

### `console_commands`

- id
- name
- command
- note nullable
- created_at
- updated_at

### `console_runs`

- id
- command_id
- status
- pid nullable
- started_at
- ended_at nullable
- exit_code nullable
- log_file_path

---

## API の方向性

```
GET    /api/console/commands
POST   /api/console/commands
PUT    /api/console/commands/:id
DELETE /api/console/commands/:id

POST   /api/console/commands/:id/run
POST   /api/console/commands/:id/stop
GET    /api/console/commands/:id/runs
GET    /api/console/runs/:id/log
GET    /api/console/runs/:id/stream
```

## UI 要件

- PC サイドバーに `コンソール` を追加する
- SP ボトムナビに `コンソール` を追加する
- 実行中コマンドは一覧上で一目で識別できる
- 停止中 / 実行中 / 異常終了を色と文言で明確に分ける
- 最新ログと履歴ログの切り替えがわかりやすい
- 失敗時はログだけでなく exit code も見える

---

## 受け入れ条件

- コマンド定義を追加・編集・削除できる
- 登録内容が再起動後も保持される
- ワンクリックで実行できる
- 実行ログが GUI で逐次表示される
- 同一コマンド再実行で上書き再起動される
- 別コマンド同士を同時実行できる
- 停止操作で穏当停止を試み、必要時のみ強制終了に移る
- 単発コマンドと常駐コマンドの両方を扱える
- 24 時間以内のログ履歴を再表示できる
- 24 時間超過の古いログがクリーンアップ対象になる
