# 探索機能 Server 実装計画（Playwright MCP 前提版）

## Summary

`doc/spec/EXPLORATION_GUI.md` を満たすため、`tasks` 系とは独立した `explorations` 系のデータモデル・API・SSE・runner を追加する。  
探索ではコード修正・Git ブランチ作成・CI 実行は行わず、AI が依頼文と内部ディスカッションを見て、自分で Playwright MCP を使うか判断する。  
Playwright MCP の設定はユーザーが手動で済ませる前提とし、server 側では MCP 設定や接続確認の仕組みは実装しない。server の責務は、探索ジョブの実行制御、証跡ファイルの回収・永続化、固定5ブロックのレポート生成、非同期 taskify に限定する。

## Implementation Changes

### 1. 共有型とイベントモデル

`shared` に探索専用型を追加し、`shared/index.ts` から re-export する。

追加型:
- `ExplorationStatus = 'draft' | 'analyzing' | 'reporting' | 'completed' | 'paused' | 'failed'`
- `ExplorationPhase = 'persona' | 'discussion' | 'explore' | 'report' | 'taskify'`
- `ExplorationSession`
- `ExplorationImage`
- `ExplorationPersona`
- `ExplorationDiscussion`
- `ExplorationArtifact`
- `ExplorationLog`
- `ExplorationTaskifyJob`
- `ExplorationEvent`

provider の callback 型は `TaskEvent` 固定をやめ、共通の `AgentStreamEvent` を新設する。  
`AgentStreamEvent` は CLI ストリームの低レベルイベントだけを持つ。
- `agent_output`
- `tool_invoked`
- `command_executed`
- `file_changed`
- `debug_log`
- `error`

既存 `TaskRunner` は `AgentStreamEvent -> TaskEvent` に変換する。  
新規 `ExplorationRunner` は `AgentStreamEvent -> ExplorationEvent` に変換する。

### 2. DB スキーマ

`server/db/schema.ts` に以下を追加する。
- `exploration_sessions`
- `exploration_images`
- `exploration_personas`
- `exploration_discussions`
- `exploration_artifacts`
- `exploration_logs`
- `exploration_taskify_jobs`

`exploration_artifacts.kind` は以下で固定する。
- `plan`
- `finding`
- `playwright-log`
- `report`
- `taskify-result`

`issue_count` は `finding` artifact 件数を正とする。  
markdown 解析で数えない。

保存先ルール:
- 添付画像: `.cognac/uploads/explorations/<sessionId>/`
- Playwright 証跡: `.cognac/artifacts/explorations/<sessionId>/playwright/`
- その他 artifact: `.cognac/artifacts/explorations/<sessionId>/`

### 3. Query 層

`server/db/queries` に探索専用 query を追加する。
- `explorations.ts`
- `exploration-images.ts`
- `exploration-personas.ts`
- `exploration-discussions.ts`
- `exploration-artifacts.ts`
- `exploration-logs.ts`
- `exploration-taskify-jobs.ts`

### 4. API

新規 `server/api/explorations.ts` を追加し、`server/index.ts` に登録する。  
`POST /api/explorations` は `application/json` と `multipart/form-data` 両対応にする。JSON は画像なし、multipart は画像付き作成。

追加エンドポイント:
- `GET /api/explorations`
- `POST /api/explorations`
- `GET /api/explorations/:id`
- `GET /api/explorations/:id/images`
- `GET /api/explorations/:id/personas`
- `GET /api/explorations/:id/discussions`
- `GET /api/explorations/:id/logs`
- `GET /api/explorations/:id/artifacts`
- `GET /api/explorations/:id/report`
- `POST /api/explorations/:id/retry`
- `POST /api/explorations/:id/taskify`
- `GET /api/explorations/:id/stream`

画像バリデーションは task 画像と揃える。
- 最大 5 ファイル
- 1 ファイル 5MB
- `png/jpeg/gif/webp`

`GET /api/status` は runner 状態を分離して返す。
- `taskRunnerStatus`
- `explorationRunnerStatus`
- `activeExecution`
- `timestamp`

### 5. 実行制御

`TaskRunner` と `ExplorationRunner` の同時実行を防ぐため、新規 `ExecutionCoordinator` を追加する。  
AI 実行は常に 1 ジョブだけ。

API:
- `acquire(kind: 'task' | 'exploration' | 'taskify', id: number): boolean`
- `release(kind, id): void`
- `getCurrent(): { kind, id } | null`

### 6. ExplorationRunner

新規 `ExplorationRunner` を追加する。  
`TaskRunner` の継承ではなく独立実装にする。

状態遷移:
- `draft -> analyzing -> reporting -> completed`
- 異常系は `paused | failed`

内部フェーズ:
1. `persona`
2. `discussion`
3. `explore`
4. `report`

`explore` フェーズでは AI が必要時に Playwright MCP を自律利用できるよう `provider.execStream()` を使う。

### 7. Taskify 非同期ジョブ

`AIでタスク化` は `exploration_taskify_jobs` を使う非同期ジョブとして実装する。  
job 実行も `ExplorationRunner` が担当し、coordinator を占有する。

### 8. Playwright MCP の扱い

今回の設計では Playwright は「server が呼ぶ外部機能」ではなく、「AI が必要なら使う MCP」として扱う。  
そのため server 側でやることは以下だけ。
- prompt に利用判断ルールを書く
- 証跡保存先を指示する
- 実行後にファイルを回収して DB 登録する
- SSE とログに反映する

server 側でやらないこと:
- MCP 設定の生成
- MCP 接続テスト
- browser install
- Playwright 実行可否の UI 切り替え
- Playwright 専用 runner

## Test Plan

最低限これを通す。
- `pnpm typecheck`
- `pnpm lint`
- `pnpm test`

追加するテスト観点:
- 探索系テーブルと index が初期化される
- `POST /api/explorations` が JSON / multipart で作成できる
- 画像サイズ・拡張子・枚数制限が効く
- `GET /api/explorations` が `hasFinalReport`, `issueCount`, `latestTaskifyStatus` を返す
- `ExplorationRunner` が `draft -> analyzing -> reporting -> completed` を正しく進める
- persona / discussion / explore / report の成果物が各テーブルに保存される
- `issue_count` が `finding` artifact 件数と一致する
- `POST /api/explorations/:id/retry` が `paused/failed` 以外を拒否する
- `POST /api/explorations/:id/taskify` が pending/running 重複 job を拒否する
- taskify 完了で複数 task が作られ、選択画像だけ task 側へコピーされる
- exploration 実行中に `.cognac/` 以外の tracked file 差分が出たら `failed` になる
- `.cognac/artifacts/explorations/<id>/playwright/` の画像・ログが正しく回収される
- SSE が `phase_start -> domain events -> phase_end -> completed` の順で流れる
- task と exploration の同時開始時に coordinator が片方を待たせる

## Assumptions / Defaults

- Playwright は Playwright MCP として AI が自律判断で使う
- MCP 設定はユーザーが事前に済ませる。server は設定支援を実装しない
- 探索本体は `execStream()` を使い、Playwright MCP 利用余地を残す
- 探索では repo tracked file の変更を禁止し、変更が出たら `failed` にする
- 証跡ファイルは AI が `.cognac/artifacts/explorations/<id>/playwright/` に保存する前提で回収する
- taskify は同期 API ではなく非同期ジョブで実装する
- 探索ログは `execution_logs` を共用せず `exploration_logs` を追加する
