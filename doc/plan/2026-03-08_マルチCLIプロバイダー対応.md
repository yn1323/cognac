# マルチCLIプロバイダー対応（Claude CLI + Codex CLI）

## Context

現在CognacはClaude Code CLI (`claude`) のみをサポートしている。
OpenAI の Codex CLI (`codex`) でもタスク実行できるようにし、設定画面からグローバルに切り替え可能にする。
全フェーズ（Phase 2 ディスカッション/プラン + Phase 3 コード実行）+ Git GUI の AI 機能を対象とする。

---

## 現状

| レイヤー | 状態 |
|---------|------|
| **claude-caller.ts** | `callClaude()` (stream-json) と `callClaudePrint()` (--print) の2関数でClaude CLI固定 |
| **stream-parser.ts** | Claude の stream-json 形式専用パーサー |
| **phase-*.ts** | 各フェーズが `callClaude` / `callClaudePrint` を直接インポート |
| **api/git.ts** | AIコミットメッセージ生成・コミット解説が `callClaudePrint` を直接呼び出し |
| **settings.tsx** | プロバイダー選択UIなし |
| **config.ts** | プロバイダー設定フィールドなし |

---

## CLIコマンド比較

| 機能 | Claude CLI (v1.x) | Codex CLI (v0.111.0) |
|------|-------------------|---------------------|
| ストリーム実行 | `claude -p --output-format stream-json` | `codex exec --json` |
| テキスト出力 | `claude --print` | `codex exec` (--json なし) |
| 自律実行 | `--dangerously-skip-permissions` | `--dangerously-bypass-approvals-and-sandbox` |
| セッション継続 | `--session-id <id>` | なし（非対応） |
| ターン制限 | `--max-turns N` | なし（非対応） |
| システムプロンプト | `--append-system-prompt-file <path>` | なし（プロンプト本文に埋め込み） |
| ツール制限 | `--allowedTools <tool>` | なし（非対応） |
| 出力形式 | chunk: `assistant`, `result` | event: `item.started/completed`, `turn.completed` |
| 環境変数除外 | `CLAUDECODE`, `CLAUDE_CODE_*` 除去必須 | 不要 |
| プロンプト入力 | stdin (ファイルをpipe) | stdin (`-` 指定) or 引数 |
| サンドボックス | なし | `-s workspace-write` / `-s read-only` |
| 一時セッション | なし | `--ephemeral` |

### Codex JSONL イベント形式

```jsonl
{"type":"thread.started","thread_id":"..."}
{"type":"turn.started"}
{"type":"item.completed","item":{"id":"item_0","type":"reasoning","text":"..."}}
{"type":"item.started","item":{"id":"item_1","type":"command_execution","command":"bash -lc ls","aggregated_output":"","exit_code":null,"status":"in_progress"}}
{"type":"item.completed","item":{"id":"item_1","type":"command_execution","command":"bash -lc ls","aggregated_output":"...","exit_code":0,"status":"completed"}}
{"type":"item.completed","item":{"id":"item_2","type":"file_change","changes":[{"path":"src/foo.ts","kind":"update"}],"status":"completed"}}
{"type":"item.completed","item":{"id":"item_3","type":"agent_message","text":"完了した"}}
{"type":"turn.completed","usage":{"input_tokens":1000,"cached_input_tokens":500,"output_tokens":200}}
```

**item type 一覧:** `agent_message`, `reasoning`, `command_execution`, `file_change`, `mcp_tool_call`, `web_search`, `todo_list`, `error`

### Step 5: Codex プロバイダー

**ファイル**: `server/runner/providers/codex-provider.ts` (CREATE)

```ts
export class CodexProvider implements CliProviderInterface {
  readonly name = 'codex'

  async execStream(options: StreamExecOptions, config: CognacConfig): Promise<CliResponse> {
    // CLI引数: codex exec --json --ephemeral -
    // dangerouslySkipPermissions → --dangerously-bypass-approvals-and-sandbox
    // システムプロンプト → プロンプト本文先頭に埋め込み:
    //   "## システム指示\n{systemPrompt}\n\n{TONE_RULES}\n\n---\n\n{prompt}"
    // --session-id, --max-turns, --allowedTools は非対応（無視）
    // CodexStreamParser で行単位パース → TaskEvent
  }

  async execPrint(options: PrintExecOptions, config: CognacConfig): Promise<CliResponse> {
    // CLI引数: codex exec --ephemeral -s read-only -
    // --json なし → stdout をテキストバッファ
    // システムプロンプト → プロンプト本文先頭に埋め込み
  }

  getCleanEnv(): NodeJS.ProcessEnv {
    // フィルタリング不要、process.env をそのまま返す
  }
}
```

**Codex 固有の注意点:**
- `codex exec` はプロンプトを引数 or stdin で受け取る。`-` を末尾に指定すると stdin モード
- `--ephemeral` でセッションファイルをディスクに残さない
- Phase 2 (read-only) では `-s read-only` で安全なサンドボックス
- Phase 3 (実行) では `--dangerously-bypass-approvals-and-sandbox` で全権限

### Step 6: Codex ストリームパーサー

**ファイル**: `server/runner/providers/codex-stream-parser.ts` (CREATE)

JSONL 行を `TaskEvent` に変換するパーサー。Claude の `StreamParser` と同じ `parse(line) → TaskEvent | null` + `getResult()` インターフェース。

**イベントマッピング:**

| Codex JSONL event | 条件 | → TaskEvent |
|-------------------|------|-------------|
| `item.completed` | `item.type === 'agent_message'` | `{ type: 'claude_output', content: item.text }` |
| `item.completed` | `item.type === 'reasoning'` | `{ type: 'thinking', content: item.text }` |
| `item.started` | `item.type === 'command_execution'` | `{ type: 'tool_invoked', tool: 'Bash', input: item.command }` |
| `item.completed` | `item.type === 'command_execution'` | `{ type: 'command_executed', command: item.command, exitCode: item.exit_code, output: item.aggregated_output }` |
| `item.completed` | `item.type === 'file_change'` | changes 配列の各エントリに対して `{ type: 'file_changed', path: change.path, operation: change.kind }` |
| `turn.completed` | — | usage を蓄積（`input_tokens`, `output_tokens`） |
| `turn.failed` | — | エラーとして reject |
| `error` | — | ログ出力、致命的ならエラー |
| `thread.started` | — | thread_id を記録（sessionId 代替） |

**getResult() の返却値:**
```ts
{
  result: string       // 最後の agent_message テキスト
  sessionId: string    // thread_id
  usage: { inputTokens, outputTokens }  // turn.completed から蓄積
}
```

### Step 7: プロバイダーファクトリー

**ファイル**: `server/runner/providers/index.ts` (CREATE)

```ts
import type { CliProvider } from '@cognac/shared'
import type { CliProviderInterface } from './types.js'
import { ClaudeProvider } from './claude-provider.js'
import { CodexProvider } from './codex-provider.js'

const providers: Record<CliProvider, () => CliProviderInterface> = {
  claude: () => new ClaudeProvider(),
  codex: () => new CodexProvider(),
}

export function createProvider(type: CliProvider): CliProviderInterface {
  const factory = providers[type]
  if (!factory) throw new Error(`未対応のCLIプロバイダー: ${type}`)
  return factory()
}

// 型・エラーの re-export
export type { CliProviderInterface, CliResponse, StreamExecOptions, PrintExecOptions } from './types.js'
export { ProcessTimeoutError, TaskCancelledError } from './types.js'
```

## 検証方法

1. `pnpm typecheck` — 型エラーなし
2. `pnpm build` — 全パッケージビルド成功
3. `pnpm test` — テスト通過
4. `pnpm dev` で起動 → 設定画面でプロバイダーを切り替え → `cognac.config.ts` に反映されることを確認
5. Claude CLI でタスク実行 → 既存動作と同じ（リグレッションなし）
6. Codex CLI でタスク実行 → JSONL イベントが TaskEvent に変換され、ダッシュボードにリアルタイム表示される
7. プロバイダー切替後の Git AIコミット → 選択中のCLIでメッセージ生成される
8. プロバイダー切替後のコミット解説 → 選択中のCLIで解説生成される
