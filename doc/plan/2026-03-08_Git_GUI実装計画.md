# Git GUI 実装計画

## Context

Cognac の Git GUI 機能（`doc/spec/GIT_GUI.md`）を実装する。
UIはハードコード済み（モックデータ表示）。本計画では **サーバーAPI の新規作成** と **クライアントの実データ接続** を行う。

---

## 現状

| レイヤー | 状態 |
|---------|------|
| **shared/types/git.ts** | 基本型定義済み（GitFile, GitBranch, GitCommit, GitRemoteStatus, CommitResult 等） |
| **client** | git-page.tsx + 各コンポーネント完成。`mock-data.ts` のハードコードデータで表示中。API呼び出しなし |
| **server** | `/api/git/*` ルートなし。`runner/git-ops.ts` に `git()` ヘルパー・`getGitStatus()` 等あり |

## 実装ステップ

### Step 1: shared 型拡張

**ファイル**: `shared/types/git.ts` (MODIFY)

API レスポンス型を追加:

```ts
// API レスポンス
export interface GitStatusResponse { files: GitFile[]; currentBranch: string }
export interface GitLogResponse { commits: GitCommit[] }
export interface GitBranchesResponse { branches: GitBranch[]; current: string }
export interface GitRemoteStatusResponse extends GitRemoteStatus {}
export interface GitCommitResponse { results: CommitResult[] }
export interface GitMergeResponse { ok: boolean; hash: string; message: string }
export interface GitPushResponse { ok: boolean; remote: string; branch: string }

// API リクエスト
export interface GitCheckoutRequest { branch: string }
export interface GitCreateBranchRequest { name: string; base?: string }
export interface GitMergeRequest { from: string; into: string }
```

`shared/index.ts` から re-export。

### Step 2: サーバー Git操作モジュール

**ファイル**: `server/runner/git-api-ops.ts` (CREATE)

既存 `git-ops.ts` はタスクランナー専用（stash管理等が絡む）なので、API用に別モジュールを作成。
`git()` ヘルパーは `cwd` 引数を必須にする。

| 関数 | コマンド | 備考 |
|------|---------|------|
| `getStatus(cwd)` → `GitFile[]` | `git status --porcelain` | 先頭2文字をパース |
| `getCurrentBranch(cwd)` → `string` | `git branch --show-current` | |
| `getLog(cwd, limit)` → `GitCommit[]` | `git log --format='%h\|%s\|%an\|%ar\|%P\|%D' -N` | 親数でマージ判定、%D でブランチバッジ |
| `getBranches(cwd)` → `GitBranch[]` | `git branch -a --format='%(refname:short)\|%(HEAD)'` | origin/ prefix → remote=true |
| `getRemoteStatus(cwd)` → `GitRemoteStatus` | `git rev-list --count HEAD..@{u}` / `@{u}..HEAD` | upstream未設定時は {0,0} |
| `checkout(cwd, branch)` | `git checkout <branch>` | |
| `createBranch(cwd, name, base?)` | `git checkout -b <name> [base]` | |
| `deleteBranch(cwd, name)` | `git branch -d <name>` | |
| `discardAll(cwd)` | `git checkout -- . && git clean -fd` | |
| `push(cwd)` | `git push -u origin <branch>` | |
| `fetchAll(cwd)` | `git fetch --all` | |
| `merge(cwd, from)` | `git merge <from> --no-ff --no-edit` | コンフリクト時は `merge --abort` して throw |
| `stageAll(cwd)` | `git add -A` | AIコミット用 |
| `getStagedDiff(cwd)` | `git diff --staged` | AIコミット用 |
| `commitWithMessage(cwd, msg)` → `CommitResult` | `git commit -m "msg"` | |

**セキュリティ**: ブランチ名バリデーション関数 `validateBranchName(name)` を用意。`/^[a-zA-Z0-9][a-zA-Z0-9\/_.\-]*$/` にマッチしない場合はエラー。

### Step 3: サーバー Git APIルーター

**ファイル**: `server/api/git.ts` (CREATE)

```ts
export function gitRouter(cwd: string) {
  const app = new Hono()
  // ... endpoints
  return app
}
```

#### Phase 1 エンドポイント

| メソッド | パス | 処理 |
|---------|------|------|
| `GET /status` | `getStatus(cwd)` + `getCurrentBranch(cwd)` | → `GitStatusResponse` |
| `GET /log` | `getLog(cwd, query.limit ?? 20)` | → `GitLogResponse` |
| `POST /discard` | `discardAll(cwd)` | → `{ ok: true }` |
| `POST /commit` | AIコミットフロー（後述） | → `GitCommitResponse` |

#### Phase 2 エンドポイント

| メソッド | パス | 処理 | ガード |
|---------|------|------|-------|
| `GET /branches` | `getBranches(cwd)` + `getCurrentBranch(cwd)` | → `GitBranchesResponse` | |
| `POST /checkout` | `checkout(cwd, body.branch)` | → `{ ok: true }` | 未コミット変更チェック |
| `POST /branch` | `createBranch(cwd, body.name, body.base)` | → `{ ok: true }` | ブランチ名バリデーション |
| `DELETE /branch/:name` | `deleteBranch(cwd, name)` | → `{ ok: true }` | 現在ブランチ削除不可 |
| `POST /push` | `push(cwd)` | → `GitPushResponse` | |
| `POST /fetch` | `fetchAll(cwd)` | → `{ ok: true }` | |
| `GET /remote-status` | `getRemoteStatus(cwd)` | → `GitRemoteStatusResponse` | |
| `POST /merge` | `merge(cwd, body.from)` | → `GitMergeResponse` | 未コミット変更チェック |

**Zodスキーマ**: 各POSTリクエストにバリデーション。既存パターン（`tasks.ts`）に準拠。

**エラーレスポンス**: 日本語メッセージ。コンフリクト時は 409、未コミット変更時は 400。

### Step 4: AIコミットフロー

`POST /api/git/commit` の実装:

1. `getStatus(cwd)` → 変更なければ 400 エラー
2. `stageAll(cwd)`
3. `getStagedDiff(cwd)` → diff取得
4. `git log --oneline -10` → スタイル参考
5. `claude --print -p "プロンプト"` で コミットメッセージ生成
   - `execSync` で呼び出し、`getCleanEnv()` パターンでenv変数をクリーン化
   - プロンプト: diff + 直近logスタイル → メッセージのみ出力指示
6. `commitWithMessage(cwd, generatedMessage)`
7. `CommitResponse` を返却

**Phase 1 では単一コミット**。分割コミットは Phase 4 で対応。

**SSE ストリーミング**: Phase 1 では同期レスポンスで実装。クライアント側は `isPending` でスピナー表示。
AIコミットの進捗ログ表示（AiCommitProgress コンポーネント）は Phase 4 でSSE化する際に接続。

### Step 6: クライアント APIメソッド

**ファイル**: `client/lib/api.ts` (MODIFY)

```ts
git: {
  status:       () => fetchJson<GitStatusResponse>('/git/status'),
  log:          (limit = 20) => fetchJson<GitLogResponse>(`/git/log?limit=${limit}`),
  branches:     () => fetchJson<GitBranchesResponse>('/git/branches'),
  remoteStatus: () => fetchJson<GitRemoteStatusResponse>('/git/remote-status'),
  discard:      () => fetchJson<{ ok: boolean }>('/git/discard', { method: 'POST' }),
  commit:       () => fetchJson<GitCommitResponse>('/git/commit', { method: 'POST' }),
  checkout:     (branch: string) => fetchJson('/git/checkout', { method: 'POST', body: JSON.stringify({ branch }) }),
  createBranch: (name: string, base?: string) => fetchJson('/git/branch', { method: 'POST', body: JSON.stringify({ name, base }) }),
  deleteBranch: (name: string) => fetchJson(`/git/branch/${encodeURIComponent(name)}`, { method: 'DELETE' }),
  push:         () => fetchJson<GitPushResponse>('/git/push', { method: 'POST' }),
  fetch:        () => fetchJson<{ ok: boolean }>('/git/fetch', { method: 'POST' }),
  merge:        (from: string, into: string) => fetchJson<GitMergeResponse>('/git/merge', { method: 'POST', body: JSON.stringify({ from, into }) }),
},
```

### Step 7: TanStack Query フック

**ファイル**: `client/hooks/use-git.ts` (CREATE)

`use-tasks.ts` パターンに準拠:

**Query hooks** (データ取得):
- `useGitStatus()` — queryKey: `['git','status']`, refetchInterval: 3000
- `useGitLog(limit=20)` — queryKey: `['git','log',limit]`, refetchInterval: 5000
- `useGitBranches()` — queryKey: `['git','branches']`
- `useGitRemoteStatus()` — queryKey: `['git','remote-status']`, refetchInterval: 10000

**Mutation hooks** (操作):
- `useDiscardAll()` → invalidate `['git','status']`, `['git','log']`
- `useAiCommit()` → invalidate `['git','status']`, `['git','log']`
- `useCheckout()` → invalidate `['git','status']`, `['git','branches']`, `['git','log']`, `['git','remote-status']`
- `useCreateBranch()` → invalidate `['git','branches']`
- `useDeleteBranch()` → invalidate `['git','branches']`
- `usePush()` → invalidate `['git','remote-status']`
- `useGitFetch()` → invalidate `['git','remote-status']`, `['git','branches']`
- `useMerge()` → invalidate `['git','status']`, `['git','log']`, `['git','branches']`

## 検証方法

1. `pnpm build` — 全パッケージビルド成功
2. `pnpm typecheck` — 型エラーなし
3. `pnpm dev` で起動 → `/git` ページで実データ表示確認:
   - 変更ファイル一覧が実際の `git status` と一致
   - コミット履歴が `git log` と一致
   - ブランチセレクターに実ブランチ一覧
   - Fetch / Push / マージ操作が動作
   - AIコミットでメッセージ自動生成＆コミット実行
4. エッジケース確認:
   - 未コミット変更ありで checkout → ブロックされる
   - 変更なしでコミット → ボタン disabled
   - リモートブランチ選択 → ローカルに作成＆切り替え
