# Git GUI 機能 — 要件定義

## Context

Cognacは現在、AIがタスクを実行→自動コミット→マージまで全自動で行う設計。
しかし、人間がコード変更を確認してからコミットしたいというニーズがあり、Fork/SourceTreeの簡易版のようなGit操作GUIを追加する。

**設計方針の転換**: コミットはすべて人間トリガーに変更。AIの自動コミット機能は廃止。

---

## 機能要件

### 1. 新規ページ `/git`

サイドバー・ボトムナビに「Git」メニューを追加し、独立したページとして配置。
SPファーストのシンプルなUI。

### 2. 変更ファイル一覧

- `git status` の結果を表示（変更・追加・削除ファイルのリスト）
- ファイルごとのステータス表示（M: Modified, A: Added, D: Deleted, ?: Untracked）
- **ファイル内のdiffは表示しない**（ファイル名とステータスのみ）
- リアルタイムまたはポーリングで更新
- **全変更を破棄する機能**（`git checkout . && git clean -fd` 相当）
  - 確認ダイアログ付き（破壊的操作のため）

### 3. コミット機能

- **ファイル選択は不要**（`git add .` 相当で全変更をステージング）
- **AIがコミットを自動分割**:
  - ユーザーが「コミット」ボタンを押すと、AIが変更ファイルを分析
  - 論理的に分けるべき場合、AIが自動的に複数コミットに分割して実行
  - 各コミットメッセージもAIが生成（直近のgit logのスタイルに合わせる）
  - ユーザーは結果を確認するだけ
- **コミットメッセージ生成**: Claude CLI (`claude -p`) を使用
  - 入力: `git diff --staged` + 直近N件の `git log` のメッセージスタイル
  - 出力: コミットメッセージ（複数コミットの場合は各メッセージ）

### 4. ブランチ操作

- セレクトボックスで**ローカル/リモートをグループ分け**表示
  - ローカルブランチ: 直接切り替え
  - リモートブランチ: 選択時に `git checkout -b <branch> origin/<branch>` でローカルに作成＆切り替え
- 現在のブランチをハイライト表示
- ブランチ切り替え（checkout）
  - **未コミット変更がある場合は警告してブロック**（先にコミットor破棄を促す）
- ブランチ作成（新規ブランチ名を入力）
- ブランチ削除（**ローカルのみ**、リモートは触らない）
  - 現在のブランチは削除不可

### 5. リモート操作（Push / Fetch / Pull）

- **Push**: 現在のブランチをリモートにpush
  - push前にリモートとの差分表示（何コミット先行しているか）
  - push結果の通知（成功/失敗）
  - force pushは**サポートしない**（安全性のため）
- **Fetch**: リモートの最新情報を取得（`git fetch`）
  - ブランチ一覧やコミット履歴を最新化
- **Pull**: リモートから現在のブランチをpull（`git pull`）
  - 未コミット変更がある場合は警告してブロック
  - コンフリクト発生時はエラー通知

### 6. コミット履歴 + グラフ表示

- 直近N件のコミット履歴を表示（`git log`）
- 表示件数は設定画面から変更可能
- 各コミット: ハッシュ（短縮）、メッセージ、日時、著者
- **コミットグラフ表示**: ブランチの分岐・マージをビジュアル表示
  - `git log --graph --all --oneline` 相当のデータをパースしてGUI描画
  - ブランチごとに色分け
  - 分岐点・マージ点を視覚的に表現

### 7. タスク連動（軽量）

- タスク詳細ページからGitページへのリンク（タスクのブランチ名を渡す）
- **タスクステータスの変更はしない** — Git操作はタスクフローから独立
- タスク実行後の自動コミット・マージは廃止し、すべて人間がGit GUIで手動操作

## API設計（Server側）

### 新規エンドポイント

```
GET    /api/git/status          — git status（変更ファイル一覧）
GET    /api/git/log?limit=N     — git log（直近N件の履歴 + グラフ情報）
GET    /api/git/branches        — ブランチ一覧 + 現在のブランチ
POST   /api/git/commit          — AIコミット実行（分割含む）
POST   /api/git/checkout        — ブランチ切り替え（未コミット変更時は400エラー）
POST   /api/git/branch          — ブランチ作成
DELETE /api/git/branch/:name    — ブランチ削除（ローカルのみ）
POST   /api/git/discard         — 全変更を破棄（git checkout . + git clean -fd）
POST   /api/git/push            — 現在のブランチをリモートにpush
POST   /api/git/fetch           — リモートの最新情報を取得
POST   /api/git/pull            — リモートから現在のブランチをpull
GET    /api/git/remote-status   — リモートとの差分（何コミット先行/遅れ）
```

### AIコミットのフロー（`POST /api/git/commit`）

1. `git status --porcelain` で変更ファイル取得
2. `git diff` で差分取得
3. `git log --oneline -10` で直近のコミットスタイル取得
4. Claude CLI に差分 + ログスタイルを渡してコミット計画を生成
   - 1コミットでOKか、分割すべきか判断
   - 各コミットの対象ファイルとメッセージを出力
5. 計画に従って `git add` + `git commit` を順次実行
6. 結果を返却（コミットハッシュ、メッセージの配列）

### ブランチ操作

- ブランチ名のドロップダウンで一覧表示・切り替え（ローカル/リモートをグループ分け）
- 「+新規」ボタンでブランチ作成ダイアログ
- ドロップダウン内に削除アイコン（現在のブランチは削除不可）

### リモート操作

- Push / Fetch / Pull ボタン
- リモートとの差分表示（何コミット先行/遅れているか）

### AIコミット実行中

- ボタン押下後、プログレス表示
- 「AIが変更を分析中...」→「コミット実行中...」→ 完了
- 完了後、コミット結果を表示（何件のコミットが作成されたか）

## エッジケース・エラーハンドリング

| ケース | 対応方針 |
|-------|---------|
| 変更ゼロでコミットボタン押下 | ボタンを無効化（変更がない時はdisabled） |
| ブランチ切り替え時に未コミット変更あり | 警告メッセージ表示してブロック。コミットor破棄を促す |
| AIコミット実行中にファイル変更 | ロック機構：コミット中はタスク実行を一時停止 |
| Claude CLIタイムアウト | エラー通知 + 手動リトライボタン表示 |
| 大量の変更ファイル（100+） | ページネーションまたはスクロール表示 |
| 現在のブランチを削除しようとした | 削除ボタンを非表示または無効化 |
| ブランチ作成時に既存名と重複 | バリデーションエラー表示 |
| push先にリモートブランチがない | `git push -u origin <branch>` で自動作成 |
| push時にリモートが先行（fast-forward不可） | エラー表示。pull を促す（force pushはサポートしない） |
| pull時にコンフリクト発生 | エラー通知 + コンフリクトファイル一覧を表示。手動解決を促す |
| pull時に未コミット変更あり | 警告してブロック。コミットor破棄を促す |
| `git` コマンド自体が失敗 | トースト通知でエラー内容を表示 |

## 影響範囲

### 変更が必要なパッケージ

| パッケージ | 変更内容 |
|-----------|---------|
| `shared/` | 新しい型定義（GitStatus, GitBranch, CommitResult等） |
| `server/` | 新規 `/api/git/*` ルート、git-ops.ts 拡張 |
| `client/` | 新規 Git ページ、ルーティング追加、サイドバー/ナビ更新、設定画面拡張 |

### 既存の git-ops.ts で再利用できるもの
- `git()` ヘルパー関数 — execSync ラッパー
- `getGitStatus()` — porcelain 出力取得
- `buildBranchName()` — ブランチ名生成
- `createTaskBranch()` — ブランチ作成ロジック
- `deleteTaskBranch()` — ブランチ削除

### 新規実装が必要なもの
- `git log` の取得・パース（グラフ情報含む）
- `git branch -a` の取得・パース
- `git checkout` の実行
- `git push` / `git fetch` / `git pull` の実行
- AI コミット分割ロジック
- Claude CLI 呼び出し（コミットメッセージ生成用プロンプト）

## 実装優先度（提案）

### Phase 1: MVP — 基本表示 + 単一AIコミット
1. Server: `/api/git/status` + `/api/git/log` + `/api/git/discard` API
2. Client: Git ページ（変更ファイル一覧 + コミット履歴リスト）
3. Server: `/api/git/commit` API（単一コミット、AIメッセージ生成）
4. Client: サイドバー/ボトムナビにGitメニュー追加
5. Client: 全変更破棄ボタン（確認ダイアログ付き）

### Phase 2: ブランチ操作 + リモート操作
6. Server: `/api/git/branches` + `/api/git/checkout` + `/api/git/branch` API
7. Server: `/api/git/push` + `/api/git/fetch` + `/api/git/pull` + `/api/git/remote-status` API
8. Client: ブランチドロップダウン（一覧・切り替え・作成・削除）
9. Client: Push / Fetch / Pull ボタン + リモートとの差分表示
10. Server: checkout/pull 時の未コミット変更チェック

### Phase 3: コミットグラフ
11. Server: `git log --graph` のパース + グラフデータ構造化
12. Client: コミットグラフのビジュアル描画（ブランチ色分け、分岐・マージ表示）

### Phase 4: AI分割コミット
13. Server: AIによるコミット分割ロジック（Claude CLI）
14. Client: 分割コミットのプログレス・結果表示

### Phase 5: タスク連動（軽量）
15. Client: タスク詳細→Git ページ連携リンク（ブランチ名を渡す）
16. Server: TaskRunner から自動コミット・マージ処理を削除

### Phase 6: 設定・UX改善
17. Client: コミット履歴表示件数設定
18. 全体: エラーハンドリング・UX改善
